# Security / Compatibility Review

Review date: 2026-09-02

## Result

The application code has no identified direct injection or code-execution path. The main security issue in the supplied project was dependency age: it was using Next.js 14.2.35, which is now outside the supported Next.js release lines.

The refactor moves the project to the maintained Next.js 16 active-LTS line and React 19, because the supplied app uses only stable App Router primitives that remain compatible with the current Next.js 16 architecture.

## Dependency changes

- Next.js: 14.2.35 → 16.3.4
- React: 18.3.1 → 19.2.8
- React DOM: 18.3.1 → 19.2.8
- Zustand: 4.5.4 → 4.5.7
- Tailwind CSS: 3.4.9 → 3.4.19
- TypeScript: 5.5.x → 5.9.3
- React type definitions updated to the React 19 line
- Node type definitions updated to the Node 24 line

The package lock is intentionally regenerated by `npm install` rather than retaining the old lockfile from the supplied project.

## Code security checks

Checked for:

- `dangerouslySetInnerHTML`
- `eval`
- `new Function`
- direct `innerHTML`
- `document.write`
- Server Actions
- middleware
- dynamic rewrites / redirects
- browser storage containing application state
- external API calls

No application code uses these mechanisms.

## Resource-bounding checks

Rendering quantities are bounded:

- equations: maximum 3
- jumps: maximum 100
- rendered sequence values: maximum 101
- visible algebra-tile values: maximum 8 inputs
- coefficients/constants: bounded to whole numbers from -100 to 100
- number-line range: bounded to a span of 200
- challenge figures: maximum 12
- challenge cells per figure: maximum 24

This prevents a numeric control from directly creating an unbounded number of DOM/SVG elements.

## State consistency fixes

The refactor also fixes several cross-component risks:

- `Jumps = n` consistently means `n` jumps and therefore `n + 1` values.
- Algebra Tiles now includes the starting value and the final value in its displayed sequence.
- A hidden equation can no longer become the active equation.
- The Lab cannot hide its final visible equation.
- Removing an active equation selects another visible equation.
- Challenge state cannot change the challenge visual after initialization.
- Mobile challenge figures use a bounded responsive layout instead of relying on a wide JPG.

## Browser hardening

The Next.js configuration adds:

- `X-Content-Type-Options: nosniff`
- `X-Frame-Options: DENY`
- `Referrer-Policy: strict-origin-when-cross-origin`
- restrictive `Permissions-Policy`
- `Cross-Origin-Opener-Policy: same-origin`
- `X-DNS-Prefetch-Control: off`
- `poweredByHeader: false`

A full Content Security Policy was deliberately not added because Next.js/React's generated runtime scripts require a nonce/hash-aware CSP configuration; a partial CSP would risk breaking the application while giving a false sense of protection.

## Validation performed

`npm run typecheck` passes against the supplied source tree after the refactor.

A production build could not be executed in the review container because the uploaded `node_modules` contains the macOS SWC binary while the review environment is Linux, and external package downloads were unavailable. The project is therefore prepared for a clean dependency install before the first build.

Recommended final verification after extraction:

```bash
rm -rf node_modules .next
npm install
npm run typecheck
npm run build
```

## Architecture refactor

Challenge-specific visuals now live inside their challenge folders. This avoids a growing global visual switch and keeps each visual's DOM generation and bounds local to the challenge that owns it.
